Status: Production Ready

Audience

- Frontend Developers

# 1. Purpose

This document defines the official folder organization of the Phone Store Frontend project.

The goals are

- Predictable project structure
- Easy onboarding
- Feature isolation
- Scalability
- Maintainability
- AI-friendly organization

Every file added to the repository MUST follow this document.

---

# 2. Folder Design Philosophy

The project follows

Feature First Architecture

NOT

Type First

Bad

src/

components/

hooks/

utils/

pages/

services/

types/

assets/

After one year

components/

contains

800 files.

Nobody knows where anything belongs.

---

Good

src/

features/

product/

cart/

wishlist/

checkout/

auth/

user/

Every feature owns itself.

# 4. Folder Responsibilities

## app/

Application bootstrap.

Contains

App.tsx

main.tsx

Error Boundary

Root Provider

Router Provider

Theme Provider

Query Provider

Never place business logic here.

---

## assets/

Contains

images

svg

fonts

videos

logos

icons

Example

assets/

logo.svg

fonts/

banner.webp

Never place feature images here.

Feature images belong inside features.

---

## config/

Contains

application configuration.

Example

api.ts

env.ts

theme.ts

routes.ts

query.ts

feature-flags.ts

No business logic.

---

## constants/

Global constants.

Examples

Role

Status

Currency

Pagination

Regex

Locale

Do not store feature constants here.

---

## generated/

Generated by OpenAPI.

Contains

client

models

requests

responses

Never edit manually.

Regenerate instead.

---

## hooks/

Only generic reusable hooks.

Examples

useDebounce

useLocalStorage

useMediaQuery

useDarkMode

Never

useProduct()

belongs here.

That belongs inside feature.

---

## layouts/

Contains application layouts.

Examples

Public Layout

Admin Layout

Checkout Layout

Authentication Layout

Dashboard Layout

Layouts contain

Header

Footer

Sidebar

Navigation

Outlet

Nothing else.

---

## lib/

Wrapper around third-party libraries.

Examples

axios.ts

dayjs.ts

chart.ts

i18n.ts

sentry.ts

Never import third-party directly across project.

Always wrap.

---

## providers/

Application Providers.

Examples

Query Provider

Theme Provider

Auth Provider

Tooltip Provider

Localization Provider

---

## routes/

Contains routing definitions.

Examples

Public Routes

Protected Routes

Admin Routes

Guest Routes

Dynamic Routes

Never write page UI here.

---

## services/

Global services.

Examples

Token Service

Storage Service

Analytics

Logger

Monitoring

Feature services belong inside features.

---

## shared/

Reusable across every feature.

Contains

components

hooks

types

icons

utils

No business logic.

---

## styles/

Global styling.

Contains

tailwind.css

theme.css

animation.css

variables.css

No feature CSS.

---

## tests/

Global testing utilities.

Contains

render helper

mock server

factories

fixtures

custom matcher

---

## types/

Global types.

Examples

ApiResponse

Pagination

Nullable

Result

Primitive

Never place Product types here.

---

## utils/

Pure utility functions.

Examples

formatCurrency

formatDate

sleep

downloadFile

copyText

Utilities never call API.

# 22. Anti Patterns

❌ Huge components folder

❌ Generic utils for everything

❌ API inside component

❌ Business logic in JSX

❌ Random helper folders

❌ Duplicate hooks

❌ Feature importing feature

❌ No barrel exports

❌ Circular dependencies

❌ Global state for everything

---

# 23. Checklist

Before creating a file

✓ Is this feature-specific?

✓ Is there an existing folder?

✓ Is naming correct?

✓ Does it duplicate another module?

✓ Is there an index.ts?

✓ Is the import path clean?

✓ Is responsibility single?

✓ Is testing folder updated?
